# Galaxy Consultant

기존 번호표 발급·호출 서버에 관리자 리포트, 이름별 조회 권한, 전체 ZIP 백업, 공통 영상 재생을 추가한 전체 코드입니다. 별도 외부 데이터베이스 연결을 새로 요구하지 않습니다.

## 시작 화면과 로그인

- `/`: 기존 매장 로그인 화면. 점코드로 매장을 선택합니다.
- 오른쪽 상단 설정 → `/console`: **관리자 로그인 / 전체 관리자** 두 버튼이 화면 중앙에 나옵니다.
- 관리자 로그인: 점코드와 인증키를 입력합니다. 입력한 점코드의 매장만 조회합니다. 첫 화면에서 매장을 선택한 뒤 들어오면 점코드가 미리 채워지며 직접 변경할 수 있습니다.
- 전체 관리자: 이름, 아이디, 인증키를 직접 입력합니다. 이름과 아이디 칸은 처음에 비어 있습니다. 고정 전체 권한 이름은 대문자 `GC`입니다.
- 등록한 관리자는 지정된 매장만 조회합니다. 고정 전체 권한 계정만 매장관리 버튼을 사용할 수 있습니다.
- 구체적인 인증키 조건과 고정 아이디는 별도로 전달하는 **인증키 방식 안내 TXT**를 확인하세요. 그 파일은 코드 ZIP에 포함하지 않습니다.

## 매장관리

전체 권한으로 로그인한 뒤 매장관리에서 인증하면 세 버튼이 표시됩니다.

1. **매장 점코드 관리**: 매장 생성, 이름·점코드 수정, 활성·비활성, 삭제, ZIP 백업·복원.
2. **매장 관리자 관리**: 추가 인증 후 관리자 이름 생성·수정·삭제, 조회 매장 체크, 전체 체크·선택 해제, 로그인 허용 여부, 영업팀 배정, 전체 ZIP 백업·복원.
3. **GC 동영상 관리**: 전 매장 공통 영상 파일 선택·저장·삭제.

이름을 저장하면 해당 이름으로 바로 로그인할 수 있습니다. 이름을 삭제하거나 권한을 수정하면 기존 로그인은 만료됩니다. 매장을 실제 삭제하면 연결된 번호표·호출·접속 기록과 해당 매장의 권한 연결도 삭제됩니다. 기록을 유지하려면 비활성을 사용하세요.

## 리포트와 보관 기간

일별·월별·연도별 탭과 달력 팝업을 사용합니다. 한국 시간 기준 최근 6개월에 걸치는 기간만 선택할 수 있고 미래 기간은 선택할 수 없습니다. 월·연도 단위 조회는 조회 기간과 실제 보관 기간이 겹치는 부분만 집계합니다.

- 발급 건수: 선택 기간에 발급된 번호표.
- 시간대별 방문객 수: 실제 사람을 감지한 수가 아니라 번호표 발급 건수.
- 평균 대기시간: 서버의 번호표 발급 시각부터 최초 호출 시각까지. 프린터의 실제 인쇄 완료 시각을 측정하는 기능은 아닙니다. 미호출 번호표는 평균에서 제외하고 재호출은 중복 계산하지 않습니다.
- 페이지 조회: 고객 화면(`/customer`, `/display`)을 해당 매장으로 연 횟수. 화면 내부의 자동 새로고침은 중복 방문으로 세지 않습니다.
- 접속 경로: `utm_source` 또는 `source`, 없으면 외부 유입 도메인 또는 직접 접속. 새로운 접속 경로 수집은 업데이트 이후부터 시작합니다.
- 영업팀별 리포트: 현재 매장의 영업팀 배정을 기준으로 집계합니다.

기존 DB에 남아 있는 발급·최초 호출 시간은 리포트에 사용할 수 있습니다. 이전 매장 목록 ZIP에는 발급·호출 이력이 없으므로 그 ZIP으로 과거 통계를 만들 수는 없습니다.

시작 시와 매일 한국 시간 00:05에 오래된 누적 기록을 날짜순으로 정리합니다. 기준은 180일 고정이 아니라 6개월 전 같은 날짜 00:00입니다. 해당 날짜가 없는 달은 말일로 보정합니다. 예를 들어 2026-10-13에는 2026-04-13 00:00보다 이른 기록을 삭제합니다.

정리 대상은 번호표·호출·접속·관리 작업 로그·누적 알림 발송 기록입니다. 매장, 관리자 이름, 조회 권한, 영업팀, 영상, 현재 번호 설정은 기간 제한으로 삭제하지 않습니다. 삭제된 옛 누적 기록은 전체 ZIP을 복원해도 같은 기준으로 다시 정리됩니다.

## 백업과 복원

새 백업은 전체 운영 데이터 ZIP(v3)입니다. 매장, 번호표·호출 이력, 번호 카운터, 접속 경로, 관리자, 조회 권한, 영업팀, 공통 영상, 알림 등록 정보가 포함됩니다. 로그인 세션, Render 환경변수, 외부 인증 서버의 인증키는 포함하지 않습니다.

- 이전 매장 ZIP(v1/v2): 매장 이름·점코드 등 매장 정보만 복원합니다. 번호표 이력, 관리자 이름과 조회 권한은 그대로 유지합니다. 백업에 없는 현재 매장은 비활성으로 변경합니다. 삭제하지는 않습니다.
- 전체 ZIP(v3): 현재 운영 데이터와 영상 목록을 백업 시점으로 교체합니다. 복원 후 다시 로그인합니다. 과거의 미발송 푸시 알림은 재발송하지 않습니다.
- 잘못된 파일이나 중복·깨진 연결 데이터는 복원하지 않습니다. 되돌릴 수 있도록 복원 전 현재 전체 ZIP을 내려받으세요.
- 전체 ZIP에는 기기 토큰 등 운영 정보가 있습니다. GitHub나 공개 사이트에 올리지 말고 별도로 보관하세요.
- 이 버전의 업로드 한도: ZIP 200MB, 압축 해제 전체 400MB, 내부 JSON 80MB, 전체 데이터 200만 행, 영상 합계 100MB. 규모가 커져 한도를 넘으면 운영 DB 자체의 백업 체계가 필요합니다.

전체 백업·복원에는 매장 관리자 관리의 추가 인증이 필요합니다. 이전 매장 ZIP은 매장 점코드 관리의 ZIP 복원에서 바로 선택할 수 있습니다.

## 영상

영상 주소는 `https://사용중인도메인/video`입니다. 이번 전체 코드 ZIP에는 제공받은 `video.mp4` 원본을 `app/static/video/video.mp4`로 포함했습니다. 영상 폴더까지 함께 배포하면 바로 반복 재생합니다.

- 서버 폴더는 `app/static/video/`입니다. MP4, WebM, M4V 파일을 넣으면 파일 이름순으로 무음 자동 반복 재생합니다. H.264 MP4 또는 브라우저가 지원하는 WebM을 사용하세요.
- 영상이 없으면 검은 빈 화면만 표시합니다.
- 여러 영상은 `01_intro.mp4`, `02_guide.mp4`처럼 이름으로 순서를 정할 수 있습니다.
- GC 동영상 관리에서 USB에 있는 파일을 선택하고 **선택한 영상 저장**을 누릅니다. 저장 완료 후에는 영상이 서버로 복사되어 USB를 빼도 됩니다.
- 저장 시 기존 공통 영상 목록을 선택한 파일 목록으로 교체합니다. 변경된 목록은 열려 있는 영상 화면에 보통 30초 이내 반영됩니다. 즉시 적용하려면 영상 화면을 새로고침하세요.
- 자동 삭제 대상이 아닙니다. 서버 디스크의 파일을 유지하면 재시작 후 같은 영상이 나옵니다.
- GitHub에 `app/static/video/` 파일을 넣어 배포하면 배포된 코드에 포함된 영상이 제공됩니다. 동영상을 바꾸지 않으면 다음 배포에서도 그 파일이 다시 제공됩니다.

**현재 Render 무료 환경의 저장 제한**: 웹에서 업로드한 영상과 서버 내부 SQLite는 Render 재배포·재시작·절전으로 사라집니다. 이 코드는 Render의 저장소 제한을 없애지 않습니다. 업로드 영상과 운영 데이터는 전체 ZIP으로 별도 백업하고 필요할 때 복원하세요. GitHub에 포함된 영상과 웹에서 업로드한 영상은 보존 방식이 다릅니다. Ubuntu의 지속적인 로컬 디스크에서는 같은 DB 파일과 영상 폴더를 유지하면 서버 프로세스를 재시작해도 유지됩니다.

공식 설명: https://render.com/docs/free#local-files-lost-on-redeploy

## 기존 Render 서비스 업데이트

1. 현재 서비스에서 기존 매장 ZIP을 먼저 내려받습니다. 기존 버전의 ZIP은 매장 정보만 포함합니다. 기존 서버의 발급·호출 이력까지 필요하면 재배포 전에 기존 DB 자체를 별도로 확보해야 합니다. 새 버전에서 지워진 과거 기록을 되살릴 수는 없습니다.
2. 전달받은 코드 ZIP을 PC에서 압축 해제합니다. `galaxyconsultant/` 안의 파일을 기존 GitHub 저장소의 같은 위치에 반영합니다. 저장소 루트에 `requirements.txt`, `render.yaml`, `app/`이 있어야 합니다. 압축 파일 자체를 저장소에 올리는 방식이 아닙니다.
3. Render에 이미 등록한 환경변수는 유지합니다. 실제 인증키·Firebase 비밀키·운영 DB·백업 ZIP을 코드와 함께 올리지 않습니다.
4. Build Command: `pip install -r requirements.txt`
5. Start Command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1`
6. 기존 Python 설정을 확인합니다. 동봉한 `.python-version`, `runtime.txt`, `render.yaml`은 기존 3.11.9 설정을 유지합니다.
7. 기존 Render 서비스가 연결한 브랜치에 변경을 반영한 뒤 배포합니다. 자동 배포가 켜져 있으면 해당 브랜치 업데이트로 배포됩니다.
8. 첫 화면과 기존 호출 기능을 확인합니다. 전체 권한으로 로그인하여 필요한 매장 ZIP을 복원하고 관리자 이름·조회 매장·영업팀을 등록합니다.
9. 설정 완료 후 새 전체 데이터 ZIP을 내려받아 따로 보관합니다. 다음 업데이트 전에도 최신 전체 ZIP을 백업하세요.

새 외부 DB를 필수로 지정하지 않았습니다. `DATABASE_URL`이 이미 있으면 그대로 사용하고, 없으면 실행 폴더의 `staff_call.db`를 사용합니다. 복원용 ZIP은 별도로 올리는 데이터 백업이며 애플리케이션 코드 ZIP과 다릅니다. 자동 ZIP 복원을 새로 설정하는 기능은 이번 관리자 콘솔 수정본에 추가하지 않았습니다.

로그인 세션과 실시간 연결은 한 서버 프로세스 기준이므로 `--workers 1`을 유지하세요. 서버가 재시작되면 재로그인이 필요합니다. 현재 버전의 코드 검사와 로컬 브라우저 검증은 완료했지만 실제 200개 매장의 동시 접속 부하·실제 인증키·실제 FCM 전송을 재현한 운영 시험은 별도로 필요합니다.

기존 음성·이미지 및 번호표 앱 연결을 유지했습니다. 구매상담 추가 음성은 사용자가 별도로 넣는 범위이며 이번 ZIP에서 새로 만들지 않았습니다. 기존 앱 연결용 내부 식별자는 호환성을 위해 유지하고 화면 브랜드는 Galaxy Consultant로 표시합니다.

| `/` | 매장 로그인 |

## 로컬 실행과 검사

```sh
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

실행 위치를 프로젝트 루트로 유지하세요. 개발 PC용 위 주소는 외부 공개 서버 설정과 다릅니다.

```sh
python -m pytest -q
node --test tests/manager_web_scope.test.cjs
```
